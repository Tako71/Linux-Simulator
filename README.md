# Linux Trainer — тренажёр Linux в терминале macOS

Терминал делится на две части: **слева** — настоящая командная строка Ubuntu,
**справа** — задание, объяснение, подсказки и автоматическая проверка.

90 заданий в 14 модулях: от `pwd` и `ls` до unit-файлов systemd, cron и bash-скриптов.

```
┌──────────────────────────────┬────────────────────────────┐
│ lab:~/lab$ chmod 750 deploy  │  M06 · Права доступа       │
│ lab:~/lab$ ls -l             │  модуль 2/6 · всего 34/73  │
│ -rwxr-x--- 1 root root ...   │                            │
│ lab:~/lab$                   │  Задание: выставь файлу    │
│                              │  ~/lab/deploy.sh права 750 │
│                              │  › _                       │
└──────────────────────────────┴────────────────────────────┘
```

## Почему Docker, а не сам macOS

macOS — это BSD, а не Linux: другой `ls` и `sed`, нет `useradd`, `apt`, `systemctl`,
`/proc`. Тренироваться на нём — значит заучивать неправильные ключи.
Поэтому команды выполняются в настоящем **Ubuntu 24.04** в контейнере: работает всё,
включая systemd и journalctl, а сломать систему невозможно — контейнер пересоздаётся одной командой.

## Установка

```bash
git clone git@github.com:Tako71/Linux-Simulator.git
cd Linux-Simulator
./ltrain
```

Подробнее по зависимостям:

```bash
# 1. Зависимости (Homebrew)
brew install --cask docker      # или: brew install orbstack (легче и быстрее)
brew install tmux

# 2. Запусти Docker Desktop / OrbStack и дождись, пока он поднимется

# 3. Первый старт (образ соберётся сам, 2–4 минуты)
cd Linux-Simulator
./ltrain
```

Python нужен только системный (`python3`), сторонних библиотек нет.

## Управление

| Команда | Что делает |
|---|---|
| `./ltrain` | запустить тренажёр |
| `./ltrain shell` | просто зайти в песочницу без уроков |
| `./ltrain stop` | остановить контейнер (прогресс и файлы сохраняются) |
| `./ltrain reset` | пересоздать песочницу с нуля |
| `./ltrain reset --progress` | ещё и обнулить прогресс обучения |
| `./ltrain rebuild` | пересобрать образ |
| `./ltrain status` | диагностика |
| `./ltrain start --no-tmux` | без разделения экрана (если tmux не нужен) |
| `./ltrain remote user@ip` | держать песочницу на своём VPS |
| `./ltrain image ghcr.io/tako71/linux-simulator:latest` | брать готовый образ из реестра |
| `./ltrain image local` | вернуться к локальной сборке |
| `./ltrain local` | вернуть песочницу на этот компьютер |

### Внутри тренажёра

Правая панель:

| Клавиша | Действие |
|---|---|
| `Enter` | проверить задание (а после успеха — перейти к следующему) |
| `h` | подсказка (по одной) |
| `s` | показать решение |
| `n` / `p` | следующее / предыдущее задание |
| `l` | список модулей и заданий, переход к любому |
| `r` | подготовить окружение задания заново |
| `q` | выход |

tmux:

* `Ctrl+b` затем `o` — переключиться между панелями (или просто кликнуть мышью)
* `Ctrl+b` затем `d` — свернуть сессию, вернуться позже через `./ltrain`
* колесо мыши прокручивает вывод

## Архитектура: что где выполняется

```
        MacBook                        │        где живёт песочница
────────────────────────────────────── │ ────────────────────────────────
 tmux                                  │
  ├── левая панель                     │   ┌──────────────────────────┐
  │    docker exec -it … bash -l  ─────────►│  контейнер Ubuntu 24.04  │
  │                                    │   │  systemd, sshd, cron      │
  └── правая панель                    │   │  /root/lab — твоя работа  │
       python3 -m trainer.panel        │   │  /var/log/ltrain/         │
       (уроки, проверки)          ─────────►│    history.log, cwd      │
                                       │   └──────────────────────────┘
 ~/.config/linux-trainer/progress.json │
```

* Твой Mac выполняет только Python-панель и tmux — это десятки мегабайт памяти.
  Никакой Linux-код на macOS не исполняется.
* Все команды идут в контейнер через `docker exec`. Контейнер — это не виртуальная машина:
  это изолированный набор процессов, использующий ядро Linux хоста.
* Проверка задания — это ещё один `docker exec` в тот же контейнер и в тот же рабочий каталог,
  где ты стоишь (панель узнаёт его из `/var/log/ltrain/cwd`, который обновляется после каждой команды).
* История команд пишется в `/var/log/ltrain/history.log` — по ней проверяются задания,
  после которых на диске не остаётся следов (`man`, `less`, `top`).
* Файлы живут внутри контейнера. `./ltrain stop` их сохраняет, `./ltrain reset` — стирает.
  Прогресс обучения хранится отдельно, на твоём Mac, и переживает любой reset.

## Ресурсы

| | |
|---|---|
| образ | ~600 МБ на диске |
| контейнер в покое | 40–80 МБ RAM |
| под нагрузкой заданий | до ~200 МБ RAM |
| ядер | хватает одного |

Итого достаточно VPS с 1 ГБ RAM и 10 ГБ диска.

## Запуск песочницы на своём VPS

Docker-клиент умеет ходить к демону по SSH. Тогда TUI остаётся на MacBook,
а Ubuntu-песочница крутится на сервере: Mac не тратит ресурсы, а сессия переживает
закрытие ноутбука.

На сервере (один раз):

```bash
curl -fsSL https://get.docker.com | sh
usermod -aG docker $USER      # затем перелогиниться
```

Вход по ключу без пароля обязателен:

```bash
ssh-copy-id user@ip-адрес     # с MacBook
ssh user@ip-адрес docker ps   # должно отработать без запроса пароля
```

На MacBook:

```bash
./ltrain remote user@ip-адрес   # или ssh://user@host:2222
./ltrain status                 # песочница: удалённо (ssh://…)
./ltrain                        # образ соберётся уже на сервере
```

Вернуться на локальный Docker: `./ltrain local`.
Настройка хранится в `~/.config/linux-trainer/config.json`, разово можно переопределить
переменной `LTRAIN_DOCKER_HOST`.

Важные оговорки для VPS:

* Уроки создают пользователей, меняют `/etc/hosts`, поднимают sshd на портах 22 и 2222,
  ломают и чинят службы — но **всё это внутри контейнера**, самой ОС сервера не касается.
* Контейнер запускается с `--privileged` (иначе не поднимется systemd), поэтому
  используй сервер, который не жалко, а не тот, где крутится продакшн.
* Порты наружу не публикуются: контейнер доступен только через `docker exec`.
* Первая сборка образа качает ~250 МБ пакетов на сервер.

## Как работает проверка

* Каждое задание имеет shell-проверку, которая запускается **в той же песочнице и в том же
  каталоге**, где ты работаешь: проверяется реальный результат (созданный файл, права,
  пользователь, запущенная служба), а не текст введённой команды.
* Часть заданий дополнительно смотрит, что нужная команда встречалась в истории
  (для `man`, `less`, `top` — там, где результата на диске не остаётся).
* Перед заданием автоматически выполняется `setup`: создаются нужные файлы, откатывается
  предыдущее состояние. Клавиша `r` повторяет подготовку.
* Прогресс хранится в `~/.config/linux-trainer/progress.json`.

## Готовый образ вместо сборки

CI собирает образ песочницы и публикует его в GitHub Container Registry.
Тогда на слабой машине не нужно ждать сборку — образ просто скачивается:

```bash
./ltrain image ghcr.io/tako71/linux-simulator:latest
./ltrain restart
```

Вернуться к локальной сборке: `./ltrain image local`.

## Разработка

```bash
python3 -m unittest discover -s tests -v
```

Тесты не требуют Docker и проверяют: уникальность идентификаторов, наличие
проверки/подсказок/решения у каждого задания, корректность shell-синтаксиса всех
фрагментов, соответствие эталонного решения проверке по истории команд и
отсутствие опасных для хоста команд.

## Как добавить свои задания

`trainer/lessons/*.py` — обычный Python. Скопируй любой модуль как образец:

```python
Task(
    id="m13-01",
    title="Название",
    brief="""Объяснение. `команды` подсвечиваются.

Задание: что нужно сделать.""",
    setup="rm -f /root/lab/x.txt",          # подготовка окружения (необязательно)
    check="test -f /root/lab/x.txt",        # код возврата 0 == сдано
    check_history=r"\btouch\b",             # regex по введённым командам (необязательно)
    hints=["Первая подсказка", "Вторая"],
    solution="touch /root/lab/x.txt",
    needs="systemd",                        # "systemd" | "net" | "" (необязательно)
)
```

Затем добавь модуль в `trainer/lessons/__init__.py`.

## Если что-то не так

* **«Docker не найден или не запущен»** — открой Docker Desktop и дождись зелёного значка.
* **systemd не поднялся** (уроки модуля 11 недоступны) — на некоторых конфигурациях Docker
  Desktop контейнеру нельзя дать cgroups. Попробуй OrbStack (`brew install orbstack`)
  или `./ltrain restart`.
* **Задания с интернетом** (`apt install`, `dig`, `curl`) требуют сети у контейнера —
  обычно она есть по умолчанию.
* **Всё сломал в песочнице** — это нормально и даже полезно: `./ltrain reset`.
* **Модуль 13 (SSH)** после задания «Ужесточаем sshd» запрещает вход root по SSH внутри
  песочницы. На доступ к самому тренажёру это не влияет: он работает через `docker exec`, а не по SSH.
* **`./ltrain remote` и «cannot connect»** — проверь `ssh user@host docker ps`. Если просит
  пароль или пишет «permission denied» — дело в ключе или в группе `docker` на сервере.
